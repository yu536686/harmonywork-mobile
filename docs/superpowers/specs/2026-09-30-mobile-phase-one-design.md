# Harmony Work Android 第一阶段设计

日期：2026-09-30

## 目标与边界

让 Android 上的小亨使用个人账户的现有加密云设置，独立完成轻量对话；手机没有连接电脑时仍能工作。界面采用已选定的「工作台优先」导航，并为后续 Harvis、任务、技能、记忆保留清楚的入口。电脑远程执行和这些能力的真实 API 属于后续独立闭环，本阶段不伪造在线状态、执行进度或结果。

## 交互与视觉

- 底部四项：首页、对话、任务、我的。首页包含开始对话、Harvis、任务、技能、记忆入口和设备状态。未接入的能力显示明确说明，不展示虚假的完成数据。
- 对话从首页和「对话」页进入；列表按最近时间排序，支持新建、打开与删除本地会话。对话页显示当前运行位置为「手机」，发送中有状态，失败可重试。
- 后续电脑任务以会话内卡片呈现目标、设备、当前步骤和成果；「任务」页聚合并返回原会话。远端未实现前仅展示功能说明和离线状态。
- 沿用 Harmony Work 紫色 `#7653E8`、浅灰背景和白色内容面。SVG 线性图标统一网格与描边。可点控件至少 48dp，文字可随系统缩放。状态同时用文字和颜色表达。
- 卡片按压反馈约 180ms，页面切换约 250ms，底部面板约 270ms；遵循系统减少动态效果设置。参考 React Bits 的卡片反馈及内容入场思路，手机上不使用依赖鼠标悬停的聚光或持续 WebGL 动画。

## 账户与密钥数据流

1. 用户输入邮箱和密码。Rust 端向 `https://api.harmonywatch.cn/api/auth/login` 登录，从响应提取 `portal_token`，仅在进程内保存会话 Cookie。
2. Rust 端用该 Cookie 获取 `/api/workbuddy/settings/snapshot`。兼容桌面端 v1、v2 云快照：Argon2id 从登录密码导出包裹密钥，XChaCha20Poly1305 解开 32 字节数据密钥，再解开设置载荷。
3. 仅读取 `aiProvider` 中的 `provider`、`model`、`harmony_api_key`。首阶段只接受 Harmony 提供商及官方 Responses 协议网关。明文 API Key 和 Cookie 不返回 React，不写日志或持久化；退出应用需要重新登录。账号下无快照、密钥缺失或解密失败时显示可恢复错误，不回退到不安全的手动明文存储。
4. 登出清理内存中的 Cookie、密钥和用户状态。本地会话按账户 ID 隔离保存，不随登出删除。

## 轻量对话数据流

- 手机 Rust 端调用 `https://api.harmonywatch.cn/v1/responses`，使用个人 `harmony_api_key` Bearer 认证、云设置里的模型名和对话消息数组；前端不直接调用模型网关。
- 只发送用户和助手的文本上下文。响应只抽取 `message.content[].output_text` 或标准 `output_text`，不把 `reasoning` 内容显示为回复。限制历史条数与单条长度，避免移动端请求无界增长。
- 本地会话保存在 WebView localStorage，按登录用户 ID 命名；每次成功发送后原子更新消息和最近时间。发送失败保留用户输入与错误提示，可点击重试；不保存 API Key、密码或 Cookie。
- 网关超时、401/403、非文本响应分别给出可理解的提示；不把完整响应体中的敏感内容显示在界面上。

## 第一阶段验收

1. 未登录时看不到虚假的账号、设备或任务状态；登录后显示真实账户姓名和模型配置状态。
2. 有兼容云快照且 Harmony 配置完整的账户，可以在电脑离线时从手机发送消息并收到独立回答；桌面端 API Key 从不出现在前端状态或存储中。
3. 关闭重开应用后，对话文本仍在；重新登录同一账户后恢复，换账户不会看到上个账户的会话。
4. 对快照缺失、密码不匹配、网络断开、网关失败进行可恢复处理。
5. 前端构建、Rust 单元测试、Windows Android Debug APK 构建通过，并在已连接真机上尝试安装和启动，记录真机限制。

## 后续独立闭环

Harvis 生图需要复用现有服务合约与积分状态；技能、任务、记忆需要服务端权限与持久化协议，以及桌面端执行代理。它们在第一阶段保留真实入口和状态说明，分别按可验证的端到端闭环开发，不用本地假数据冒充远端数据。
